# مهارة تصميم وهندسة منصة الـ SaaS (SaaS Platform Design & Architecture)

تم إعداد هذه المهارة لتكون **المرجع الصارم، الدائم، والإلزامي** لأي وكيل ذكاء اصطناعي (AI Agent) أو مطور يعمل على هذا المشروع، لضمان استمرارية نفس النهج المعماري، الهندسي، والتصميمي عالي المستوى دون أدنى انحراف.

---

## 1. المعمارية البرمجية والمصادقة (Authentication & Architecture)

- **الهيكلية المعمارية الموديلية للبيئتين (`Web` مقابل `Api`)**:
  - **موديول الويب وإدارة المنصة (`app/Modules/Web/`)**:
    - مخصص **حصراً واستثنائياً لمالك المنصة وإدارتها (`Admin`)**.
    - يشمل: المتحكمات، الموديلات (`Admin`, `Plan`, `Subscription`, ...)، الخدمات، طلبات التحقق المنظمة فرعياً، الترحيلات والبذور في (`Database/`)، ومسارات الويب في (`routes/web.php`).
    - يعتمد على جلسات الويب القياسية (`Natural Session Auth`) وقوالب Blade.
    - **حظر تام لقوالب Blade لغير المشرفين**: يُمنع منعاً باتاً إنشاء مسارات ويب أو قوالب Blade لواجهات الموردين أو المشتركين داخل هذا النطاق.
  - **موديول محرك الأداة والواجهات البرمجية (`app/Modules/Api/`)**:
    - مخصص **حصراً لعملاء ومستخدمي وموردي الأداة**.
    - منطق البيزنس (Core Business Logic)، محرك الامتثال، واعتماد الموردين، وإدارة المتطلبات والشهادات، مستقره في الباك إند هنا.
    - التخاطب يتم **حصرياً عبر واجهات برمجية RESTful APIs** منظمة في `routes/api.php` تحت `/api/v1/`.
    - المصادقة تعتمد حصرياً على الرموز الرقمية الموثقة (Laravel Sanctum / Bearer Tokens)، لتغذية **مشروع فرونت إند خارجي مستقل تماماً (Decoupled Frontend)**.

- **مبدأ صاحب المصلحة الأكبر وصفر مجلدات مصطنعة (Strictly Zero `Shared` Folders)**:
  - كل موديل يتبع الموديول الذي يدير 90% من عملياته.
  - الملفات المشتركة الحقيقية والمتكافئة (50% - 50%) تعيش حصراً في أماكن لارافيل الافتراضية في جذر `app/` و `database/`:
    - `app/Models/Tenant.php`, `app/Models/Scopes/TenantScope.php`, `app/Services/Tenants/TenantService.php`
    - `app/Traits/BelongsToTenant.php`, `app/Traits/HasPlanFeatures.php`
    - `database/migrations/` (لجداول `tenants` و `failed_jobs`).

- **معايير متحكمات الأساس واستجابات الـ API (Base Controllers & API Standardization)**:
  - حذف مجلد `app/Http/` القديم بالكامل.
  - **متحكم الويب الأساسي (`App\Modules\Web\Http\Controllers\Controller`)**: كلاس تجريدي ترث منه متحكمات الويب.
  - **متحكم الـ API الأساسي الخفيف (`App\Modules\Api\Http\Controllers\ApiController`)**:
    - كلاس مستقل تماماً ترث منه كافة متحكمات الـ API حصرياً.
    - يوفر دوال الرد الموحدة:
      - `successResponse($data = null, string $message = 'تمت العملية بنجاح', int $status = 200)`
      - `errorResponse(string $message = 'حدث خطأ ما', int $status = 400, $errors = null)`
    - **يُمنع منعاً باتاً كتابة `response()->json([...])` يدوياً داخل متحكمات الـ API**، ويجب دائماً استخدام `$this->successResponse(...)` و `$this->errorResponse(...)`.
    - صيغة JSON الموحدة: النجاح (`success: true, message, data`)، والخطأ (`success: false, message, errors`).

- **معايير تسلسل البيانات ومنع التكرار في استجابات الـ API (Anti-Duplication & Single Source of Truth)**:
  - **حظر تام لتكرار كائن الباقة في جذر الاستجابة (`data.plan`)**: كائن الباقة يتبع المنشأة ويُدرج حصراً داخل `data.tenant.plan`. يُمنع منعاً باتاً تكرار كائن `plan` في الجذر لتجنب تضارب الحالة ولتخفيف حمولة البيانات.
  - **إلزامية دوال التسلسل المركزية للموديلات (`Tenant::toApiArray()` و `Plan::toApiArray()`)**:
    - يُمنع منعاً باتاً تجميع مصفوفات المنشأة أو الباقة يدوياً داخل الـ Controllers.
    - تستدعي كافة متحكمات الـ API (`ApiAuthController`, `ApiTenantRegistrationController`, `ApiCompanyController`, `ApiSubscriptionController`) دالة `$tenant->toApiArray()` لتوحيد الحقول الصادرة (`id`, `name`, `slug`, `company_cr`, `email`, `phone`, `status`, `plan`).
  - **العقد المعياري لاستجابات الاشتراكات (`/subscription` / `upgrade` / `cancel`)**:
    - تتكون الاستجابة حصراً من كائنين نظيفين:
      1. `tenant`: كامل بيانات المنشأة مع باقتها الرسمية المعتمدة وحدودها وميزاتها (`$tenant->toApiArray()`).
      2. `subscription`: تفاصيل الاشتراك الفعلي الصافية (`id`, `status`, `billing_cycle`, `current_period_end`, `price`, `currency`).

- **حوكمة دورة حياة المنشآت والاشتراكات (Tenant Provisioning & Subscription Lifecycle)**:
  - **التأسيس الذري الثلاثي للمنشأة (`Atomic Provisioning`)**:
    - يتم إنشاء المنشأة عبر `TenantService::createTenantWithSubscription` التي تضمن إنشاء: المنشأة (`Tenant`)، المستخدم الأول (`User`)، والاشتراك المبدئي (`Subscription`) كعملية ذرية واحدة داخل `DB::transaction`.
  - **الباقة الافتراضية عند التسجيل**: يُسند لكل منشأة جديدة تلقائياً اشتراك في الباقة المجانية (`free`) كافتراض أساسي لضمان امتلاكها خطة عمل صالحة فور التأسيس.
  - **إدارة ترقية وتبديل الباقات (`SubscriptionService::changePlan`)**: يتم التبديل بسلاسة عبر فحص وجود السعر الفعلي وتحديث سجل الاشتراك ومحددات الباقة.
  - **الإلغاء الآمن للاشتراكات والعودة للباقة المجانية (`SubscriptionService::cancelSubscription`)**: عند إلغاء اشتراك مدفوع، يُوسم الاشتراك كـ `canceled` وتعود المنشأة تلقائياً للباقة المجانية الافتراضية.
  - **الإنهاء الآمن لحساب المنشأة (`TenantService::terminateAccountSafely`)**: سحب كافة رموز الدخول الرقمية (Revoke Tokens)، وتعطيل حالة المنشأة إلى `suspended` دون كسر العلاقات المشتركة.

- **الحفاظ التام على المجلدات الفرعية لطلبات التحقق (Requests Subfolders)**:
  - تنظيم الـ Requests داخل مجلدات متخصصة بحسب الكيان (مثل `Requests/Auth/`, `Requests/Profile/`, `Requests/Plans/`, `Requests/Features/`, `Requests/Tenants/`).
  - صياغة رسائل عربية مخصصة وواضحة لكافة قواعد التحقق.

- **تنظيم الترحيلات ومزودي الخدمة**:
  - ترحيلات وبذور الويب في `app/Modules/Web/Database/`.
  - ترحيلات الـ API في `app/Modules/Api/Database/Migrations/`.
  - تسجيل الترحيلات عبر `$this->loadMigrationsFrom(...)` داخل `WebModuleServiceProvider` و `ApiModuleServiceProvider`.

- **جدول وموديل الإدارة ومستخدمي الـ API**:
  - حساب السوبر أدمن: `App\Modules\Web\Models\Admin` على جدول `admins`.
  - مستخدمو الأداة: `App\Modules\Api\Models\User` على جدول `users`.
  - لا يوجد حقل `is_super_admin` في جدول `admins`؛ جدول `admins` مخصص كلياً لإدارة المنصة السحابية.

- **التعامل الطبيعي مع لارافيل (No Explicit Guards)**: لا تضع أي `guard('web')` أو `guard('admin')`. استخدم دوال لارافيل القياسية والمباشرة:
  - `Auth::user()`
  - `Auth::attempt($credentials, $remember)`
  - `Auth::check()`
  - `Auth::logout()`
  - وحماية مسارات الويب حصرياً عبر `middleware('auth')`.

- **أسلوب المتحكمات والمسارات**:
  - أسلوب دوال بسيط بدون حشو (`clean controller methods`).
  - حقل "تذكرني" (`remember`) بـ `value="1"` وقاعدته `['nullable']`.
  - مسارات مباشرة ونظيفة: `/login`, `/register`, `/dashboard`, `/logout`. المسار الرئيسي `/` يوجه تلقائياً إلى `/login`. توجيه الدخول صراحة إلى `route('dashboard')`.

## 2. معايير وهوية التصميم (Design System & Aesthetics)

تم بناء التصميم وفق أعلى معايير منصات الـ SaaS العالمية (Linear, Stripe, Supabase, Vercel) بمبادئ صارمة ضد العشوائية (Anti-AI-Slop).

### الخط والأيقونات:
- **الخط الرسمي الحصري**: **`IBM Plex Sans Arabic`** من Google Fonts:
  ```html
  <link href="https://fonts.googleapis.com/css2?family=IBM+Plex+Sans+Arabic:wght@300;400;500;600;700&display=swap" rel="stylesheet">
  ```
  يُمنع استخدام أي خطوط افتراضية أخرى. العناوين: `font-weight: 700; letter-spacing: -0.01em;`.
- **الأيقونات الرسمية الحصرية**: **`Remix Icon`** (`<i class="ri-..."></i>`).
  - **حظر تام للإيموجي (Strictly No Emojis)**: يُمنع نهائياً استخدام أي إيموجي (مثل 📊, 🚀, 👤) في أي نص أو عنوان أو زر أو جدول، ويجب استبدالها دائماً بأيقونات فكتور عبر وسم `<i class="ri-..."></i>`.

### التخطيط واستغلال الشاشات (Fluid Full-Width 100%):
- **عرض كامل بدون قيود**: حاوية المحتوى `.content-container` تشغل **100% من العرض دائماً** (`width: 100%; max-width: 100%; padding: 1.75rem 2rem;`).
- يُمنع تماماً استخدام `max-width: 1200px` أو `max-width: 1400px` مع `margin: 0 auto;`.
- **معمارية تثبيت الهيكل وحصر التمرير في المحتوى الأوسط (SaaS App Viewport Shell)**:
  - قفل التمرير على النافذة العامة للتطبيق (`body:not(.auth-page) { height: 100vh; overflow: hidden; }`).
  - تثبيت الشريط العلوي (Topbar) والقائمة الجانبية (Sidebar) بنسبة 100% خارج التمرير (`flex-shrink: 0`).
  - التمرير الرأسي ينحصر حصرياً داخل منطقة المحتوى الأوسط والتذييل (`.main-scroll-area`) مع شريط تمرير نحيف وأنيق بحجم 6px.

### القائمة الجانبية والشريط العلوي:
- **القائمة الجانبية (Sidebar)**: ثابتة بعرض `255px` في الجانب الأيمن (RTL).
  - عناصر القائمة: حجم موحد `font-size: 0.965rem;` مع وزن `font-weight: 500;` للروابط العادية، وفارق سماكة هادئ وناعم لحالة النشط `font-weight: 600;`.
  - بطاقة المشرف: مكانها الإلزامي هو **أسفل القائمة الجانبية (Sticky Sidebar Footer)** مع صورة رمزية (Avatar) تعرض الحرف الأول، وقائمة منبثقة تفاعلية (Dropdown).
- **هوية ولوجو البراند (VendorProof)**: اسم المنصة الرسمي هو **VendorProof**، وشعارها درع الاعتماد `<i class="ri-shield-check-fill"></i>` مع وسم `.brand-accent`.
- **الشريط العلوي (Topbar)**: مخصص لمسار التنقل (Breadcrumbs)، حقل البحث مع اختصار `Ctrl+K`، وزر التبديل السلس بين الوضعين الليلي والفاتح (`#themeToggleBtn`).

### لوحة الألوان المزدوجة والتباين العالي (Dual-Theme System):
- **الوضع الفاتح (Light Mode - الافتراضي)**:
  - الخلفية العامة: `#f8fafc`. الأسطح والبطاقات: `#ffffff` مع حواف خفيفة `border: 1px solid #e2e8f0`. النصوص الرئيسية: `#09090b`. النصوص الثانوية: `#334155`.
- **الوضع الليلي المعتمد (Dark Mode - `[data-theme="dark"]`)**:
  - الخلفية العامة: `#09090b` (أسود كربوني عميق Zinc-950). الأسطح والبطاقات: `#121316`. الحدود: `#222328`. النصوص الرئيسية: `#f4f4f5`. النصوص الثانوية: `#a1a1aa`. هيدر الجدول: `#121316` بنص ناصع `#f4f4f5`. هوفر صفوف الجدول: `#18191e`.
- **قاعدة الزر الأساسي عالي التباين (High-Contrast Inverted Primary CTA)**:
  - في الوضع الفاتح: خلفية `#09090b` بنص أبيض ناصع.
  - في الوضع الليلي: خلفية بيضاء ناصعة `#f4f4f5` بنص كربوني داكن عريض `#09090b` (لمنع كارثة اختفاء النصوص أو ظهور نص أبيض على زر أبيض)، وعند الهوفر `#e4e4e7` مع بقاء النص داكناً ومقروءاً.

### قواعد الجداول والبيانات الصارمة:
- **معايير ترويسة الجداول ووضوح النصوص (High-Contrast Readable Table Headers)**:
  - حجم الخط في ترويسة الجدول (`.data-table thead th`): مقروء بدقة **`font-size: 0.88rem; font-weight: 600;`** مع إلغاء أي تباعد اصطناعي بين الحروف (`letter-spacing: normal;`).
  - في الوضع الفاتح: نص داكن وعالي التباين `#1e293b` على خلفية `#f8fafc` مع حد سفلي أنيق.
  - في الوضع الليلي: نص ناصع وواضح جداً `#f4f4f5` على خلفية فحمية `#121316` وحد سفلي `#27272a`.
- **معايير عرض الحالات وحظر البيدجات والأطر (Strictly No Badges/Borders for Statuses)**:
  - **حظر تام وشامل للبيدجات والأطر للحالات في كامل المشروع (`.status-pill`)**: يُمنع منعاً باتاً إعطاء الحالات أي خلفية بيضاوية ملوّنة (Pill background) أو إطار (Border) في أي صفحة أو جدول (`background: transparent !important; border: none !important; padding: 0 !important;`).
  - تظهر جميع الحالات بنص نظيف موحد، تسبقه نقطة دائرية صغيرة هادئة (6px) فقط (`.status-dot`):
    - `• نشط` (نقطة خضراء `#16a34a` / `#4ade80`).
    - `• تجربة مجانية` (نقطة زرقاء هادئة `#3b82f6`).
    - `• بانتظار التجديد` (نقطة برتقالية `#d97706` / `#fbbf24`).
    - `• ملغي / معلق` (نقطة حمراء `#dc2626` / `#f87171`).
- **عرض الأسماء النقية في الجداول وحظر الحشو تحت الأسماء (Display Only Names in Table Cells - Zero Secondary Clutter)**:
  - في خلايا المنشآت والمشتركين والشركات في كافة الجداول (`.subscriber-cell`): يُعرض اسم المنشأة/المشترك فقط بجانب الأفتار الرمزي، ويُمنع منعاً باتاً حشر أرقام السجلات التجارية (`س.ت`) أو البريد الإلكتروني أو أي نصوص وبيانات فرعية تحت الاسم داخل نفس الخلية لتوحيد ارتفاع الصفوف والمقروئية الهادئة.
- **استئصال التلوين الأخضر والألوان المتنافرة في الشارات (Strictly Neutral Badges Only)**:
  - يُمنع منعاً باتاً إعطاء الشارات (`.trend-badge`) أي خلفيات خضراء ملونة (`trend-up`) أو ألوان متنافرة. تلتزم كافة الشارات بالثيم الحيادي الهادئ الموحد (`trend-stable`): خلفية رمادية هادئة متكيفة، نص وأيقونة داكنة واضحة، وإطار رقيق محدد.
- **نظام القوائم المنسدلة ثلاث نقاط في الجداول (Floating Fixed Portal Table Dropdowns)**:
  - تظهر القوائم دائماً عبر تموضع ثابت (`position: fixed; z-index: 99999;`) للتحليق فوق حدود الجدول ومنع اقتطاعها بواسطة `overflow`، مع كشف المساحة تلقائياً (Dropup / Dropdown) والإغلاق التلقائي عند التمرير.
- **تنقية كروت الباقات (Clean SaaS Pricing Cards)**:
  - بطاقات التسعير في الأعلى مخصصة لعرض الهوية والسعر وقائمة الميزات، وخالية تماماً من الأزرار أو عدادات المشتركين؛ كافة عمليات الإدارة والتعديل تُسند لجدول الحوكمة الرسمي المخصص أسفل البطاقات.
- **جدول الباقة الواحدة للميزات والحدود (Single Plan Feature Matrix)**:
  - اعتماد جدول الـ 3 أعمدة الموحد للباقة الواحدة (`الميزة / الحد التشغيلي`، `النوع`، `القيمة / التفعيل للباقة`).
- **حظر عرض وحدات قياس مصطنعة والالتزام بالأرقام النقية (Display Only Pure Numbers for Limits - Zero Fake Mock Units)**:
  - تُعرض الحدود العددية (`limit`) كأرقام نقية فقط (مثل: `3`، `50`، `100`) أو كلمة `غير محدود` للقيمة غير المحدودة (`-1`).
  - يُمنع منعاً باتاً اختلاق أو عرض أي وحدات قياس مصطنعة أو كلمات لاحقة (مثل "مستخدمين"، "مورد"، "جيجابايت"، "يوماً") ما لم تكن مسجلة ومدعومة صراحة في حقل مخصص في قاعدة البيانات.
- **حظر أشرطة الهيرو وكروت البروفايل العائمة (Strictly No Hero Banners / Ribbons)**:
  - يُمنع نهائياً إنشاء أي كارت هيرو عائم؛ كل صفحة تعتمد حصرياً على **شريط عنوان الصفحة القياسي (`.page-title-bar`)** يليه لوحات البيانات الرسمية للنظام (`.card-panel`).

## 3. معايير التجاوب التام والتصميم المتكيف (Enterprise Responsive Standards)

- **الهيدر والشريط العلوي في الشاشات الصغيرة (`< 768px`)**:
  - **ثبات كامل لصف الهيدر**: الهمبرغر، مسار التنقل (Breadcrumbs)، زر البحث، **وزر الوضع الليلي/النهاري** يظلون ظاهرين بشكل دائم جنباً إلى جنب في الشريط العلوي دون أي اختفاء أو اقتطاع.
  - **شريط البحث المنسدل أسفل الهيدر (Drop Down Below Header)**:
    - **حظر تام لتغطية صف الهيدر أو إخفاء عناصر الهيدر (`Strictly No Full-Topbar Overlay`)**:
    - شريط البحث ينسدل حصرياً **أسفل الهيدر مباشرة** (`top: 100%; left: 0; right: 0; width: 100%;`) بنعومة وانسيابية (`animation: searchBarDropDown`).
    - يحتوي على تركيز تلقائي (`auto-focus`)، أيقونة فكتور، وزر إغلاق شفاف، وإغلاق سلس بالنقر خارجه، أو النقر على أيقونة البحث مجدداً، أو الضغط على `Escape`.

## 4. العزل المعماري التام للجافاسكريبت (Zero Inline JS & Zero Inline Handlers)

- **حظر تام للأكواد المضمنة (Strictly Zero Inline `<script>`)**:
  - يُمنع منعاً باتاً كتابة وسوم `<script>` تحتوي على منطق تفاعلي أو معالجة أحداث داخل أي ملف أو قالب Blade (باستثناء سطرين في `<head>` لمنع وميض الثيم FOUC).
  - يجب فصل كافة وظائف الجافاسكريبت حصرياً في ملفات نمطية مخصصة ومستقلة داخل `public/js/`.
- **حظر تام لمعالجات الأحداث المباشرة داخل HTML (Zero Inline Event Handlers)**:
  - يُمنع منعاً باتاً كتابة سمات `onclick="..."`، `onchange="..."`، `onsubmit="..."`، `oninput="..."` في أي عنصر أو وسم HTML.
  - يجب استبدالها دائماً بتفويض الأحداث (Event Delegation):
    - **الإشعارات السريعة**: سمة البيانات `data-toast="..."` و `data-toast-type="success|error"`.
    - **تأكيد الحذف والنماذج**: سمة البيانات `data-confirm="..."`.
    - **تفاعل الحدود وخيارات غير محدود**: كلاس `.limit-unlimited-checkbox` مع سمة `data-target="..."`.
- **هيكلية مكتبة ملفات الـ JS المركزية في `public/js/`**:
  - `public/js/admin-core.js`: المحرك الأساسي للمنصة (الثيم، السايدبار الموبايل، البحث المنسدل، قائمة المشرف، قوائم الجداول ثلاث نقاط العائمة، تفويض `data-toast` و `data-confirm`).
  - `public/js/notyf-init.js`: المحرك المركزي لإشعارات Notyf وقراءة رسائل الجلسة فلاش وأخطاء التحقق من حاوية البيانات الصامتة `<div id="flashToastData">`.
  - `public/js/table-filters.js`: محرك الفلترة والبحث اللحظي المباشر لجداول المنشآت، الاشتراكات، والميزات.
  - `public/js/plan-limits.js`: محرك تفاعلات الحدود التشغيلية وخيارات "غير محدود" في الباقات.
  - `public/js/dashboard-charts.js`: محرك الرسوم البيانية التفاعلية وقراءة البيانات من سمات HTML المخصصة بدون أي سكريبت داخل الداشبورد.
- **تمرير بيانات الخادم إلى الجافاسكريبت**:
  - يتم حصرياً عبر سمات البيانات (HTML Data Attributes مثل `data-revenue-labels`, `data-success`) في حاويات صامتة، ويُمنع منعاً باتاً خلط المتغيرات البرمجية أو كائنات `@json` داخل وسوم السكربت.

## 5. نظام إشعارات Notyf التفاعلية (Toast Standards)

- **حظر تام للتنبيهات الثابتة (No Static Flash Banners)**: يُمنع منعاً باتاً كتابة بنرات التنبيه الثابتة المزعجة (`.alert-success` و `.alert-danger`) داخل قوالب Blade.
- **التضمين والربط المركزي الموحد**:
  - يتم تضمين الإشعارات حصرياً عبر `@include('admin.partials.notyf')` في قوالب التخطيط الأساسية قبل إغلاق `</body>`.
  - التقاط رسائل الجلسة فلاش لارافيل وأخطاء التحقق يتم عبر الحاوية الصامتة `<div id="flashToastData">` ومحرك `notyf-init.js`.
- **هندسة اتجاه RTL وزر الإغلاق والأبعاد**:
  - **الترتيب الإلزامي**: `[أيقونة فكتور على اليمين] -> [نص الرسالة بالوسط] -> [زر إغلاق شفاف على اليسار]`.
  - **حظر الشريط المظلم لزر الإغلاق**: يجب أن تكون خلفية زر الإغلاق شفافة دائماً (`background-color: transparent !important;`).
  - **الأبعاد المدمجة**: `min-height: 44px`، وهوامش داخلية متناسقة، وتعطيل تموج الحركة `ripple: false`.
  - **لوحة الألوان الهادئة**: النجاح (`#15803d` / Emerald)، الخطأ (`#b91c1c` / Ruby).
