# معايير ودستور تطوير وتصميم المنصة (SaaS Admin Platform Standards)

تم إعداد هذا المستند ليكون **المرجع الصارم، الدائم، والإلزامي** لأي نموذج ذكاء اصطناعي (AI Agent) أو مطور يعمل على هذا المشروع في أي محادثة أو جلسة حالية أو مستقبلية، لضمان استمرارية نفس النهج المعماري والتصميمي عالي المستوى دون أدنى انحراف أو اجتهاد عشوائي.

## 1. المعمارية البرمجية والمصادقة (Backend & Authentication)

### الهيكلية المعمارية الهجينة الصارمة (Strict Hybrid SaaS Architecture):
- **نطاق الويب وإدارة المنصة (SaaS Admin Domain)**:
  - مسارات الويب في `routes/web.php` وقوالب Blade المربوطة بـ `admin.css` مخصصة **حصراً واستثنائياً لمالك المنصة وإدارتها (Super Admin / Platform Admin)**.
  - كافة عمليات إدارة المشتركين، الخطط، الاشتراكات، الفواتير، التقارير الإدارية، وإعدادات النظام تتم هنا عبر جلسات الويب القياسية (`Natural Session Auth`).
  - **حظر تام لقوالب Blade لغير المشرفين**: يُمنع منعاً باتاً إنشاء مسارات ويب أو قوالب Blade لواجهات الموردين أو المشتركين أو عملاء الساس داخل هذا النطاق.
- **نطاق محرك الأداة الفعلية للموردين والاعتماد (Core Tool Backend & Headless API)**:
  - منطق البيزنس (Core Business Logic)، محرك قواعد البيانات، حسابات الامتثال، واعتماد الموردين، وإدارة المتطلبات والشهادات، مكانه ومستقره البرمجي في هذا الباك إند (`App\Models`, `Services`, `Actions`).
  - التخاطب واستهلاك هذه الأداة يتم **حصرياً عبر واجهات برمجية RESTful APIs** منظمة ونظيفة في `routes/api.php` مع وحدات تحكم مستقلة (`App\Http\Controllers\Api\...`) وموارد (`API Resources`).
  - مصادقة مستخدمي وموردي الأداة في الـ API تعتمد حصرياً على الرموز الرقمية الموثقة (Laravel Sanctum / Bearer Tokens)، مع الفصل التام عن جلسات الويب الخاصة بلوحة تحكم المشرف.
  - تغذي هذه الـ APIs **مشروع فرونت إند خارجي مستقل تماماً (Decoupled / Headless Frontend)** مخصص للموردين والمشتركين والشركات.

### الكيان الإداري المخصص (`Admin` Entity):
- الكيان الوحيد لمدير المنصة الأساسي (السوبر أدمن) هو جدول وموديل `Admin` (`admins` table).
- مسار الموديل المعتمد: `App\Modules\Web\Models\Admin`.
- جدول وموديل `users` مخصص حصرياً لمستخدمي منشآت الأداة عبر الـ API وموقعه: `App\Modules\Api\Models\User`.
- لا يوجد حقل `is_super_admin` في جدول `admins`؛ جدول `admins` مخصص كلياً لإدارة المنصة السحابية.

### قاعدة التعامل الطبيعي مع المصادقة (No Explicit Guards):
- يُمنع منعاً باتاً استدعاء أو كتابة قارد صريح في الكود مثل `Auth::guard('web')` أو `guard('admin')`.
- يجب دائماً استخدام دوال لارافيل القياسية والمباشرة في كافة المتحكمات والقوالب:
  ```php
  Auth::user()      // جلب بيانات المشرف المسجل
  Auth::attempt()   // محاولة تسجيل الدخول
  Auth::check()     // التحقق من حالة الجلسة
  Auth::logout()    // تسجيل الخروج
  ```
- حماية المسارات تتم دائماً عبر الوسيط القياسي المباشر `middleware('auth')`.

### التحقق ونظافة المتحكمات (Form Requests):
- يُمنع كتابة مصفوفات التحقق `$request->validate([...])` داخل دوال المتحكمات مباشرة.
- يجب دائماً إنشاء كلاسات `Form Request` مخصصة في مجلد `app/Http/Requests/Admin/` (مثل `AdminLoginRequest`، `AdminRegisterRequest`) مع رسائل عربية مخصصة وواضحة.
- حقل "تذكرني" (`remember`) في نموذج تسجيل الدخول يكون دائماً بـ `value="1"` وقاعدته في الـ Request هي `['nullable']`.

### الروابط والتوجيهات (Routing):
- مسارات لوحة التحكم تكون مباشرة ونظيفة بدون بادئات زائدة في أسماء الروابط أو العناوين في `routes/web.php`:
  - تسجيل الدخول: `/login` (الاسم: `login`)
  - التسجيل: `/register` (الاسم: `register`)
  - لوحة التحكم: `/dashboard` (الاسم: `dashboard`)
  - تسجيل الخروج: `/logout` (الاسم: `logout`)
- المسار الرئيسي `/` يوجه تلقائياً إلى `/login`.
- توجيه المشرف بعد نجاح الدخول يكون دائماً وبشكل صريح إلى `route('dashboard')`.

## 2. نظام وهوية التصميم (UI/UX Design System)

تم بناء التصميم وفق أعلى معايير منصات الـ SaaS العالمية (Stripe, Linear, Supabase, Vercel) بمبادئ صارمة ضد العشوائية (Anti-AI-Slop).

### الخط الرسمي (Typography):
- الخط الرسمي الوحيد للمشروع هو **`IBM Plex Sans Arabic`** المستورد من Google Fonts:
  ```html
  <link href="https://fonts.googleapis.com/css2?family=IBM+Plex+Sans+Arabic:wght@300;400;500;600;700&display=swap" rel="stylesheet">
  ```
- يُمنع استخدام أي خطوط افتراضية أخرى (مثل Arial, Tahoma, Segoe UI).
- العناوين الرئيسية: `font-weight: 700; letter-spacing: -0.01em;`.
- عناصر القائمة الجانبية: حجم موحد `font-size: 0.965rem;` مع وزن `font-weight: 500;` للروابط العادية، وفارق سماكة هادئ وناعم لحالة النشط `font-weight: 600;`.

### الأيقونات الرسمية (Vector Icons Only):
- مكتبة الأيقونات الرسمية الحصرية هي **`Remix Icon`** عبر الـ CDN:
  ```html
  <link href="https://cdn.jsdelivr.net/npm/remixicon@4.2.0/fonts/remixicon.css" rel="stylesheet" />
  ```
- **حظر تام للإيموجي (Strictly No Emojis)**: يُمنع نهائياً استخدام أي إيموجي (مثل 📊, 🚀, 👤) في أي نص أو عنوان أو زر أو جدول داخل كافة الواجهات، ويجب استبدالها دائماً بأيقونات فكتور عبر وسم `<i class="ri-..."></i>`.

### التخطيط واستغلال الشاشات (Fluid Full-Width 100%):
- **ممنوع حصر المحتوى في المنتصف**: يُمنع تماماً استخدام `max-width: 1200px` أو `max-width: 1400px` مع `margin: 0 auto;`.
- حاوية المحتوى `.content-container` في القالب العام [app.blade.php](file:///c:/Users/ZBook/Desktop/backend/resources/views/admin/layouts/app.blade.php) مصممة لتشغل **100% من العرض المتاح** (`width: 100%; max-width: 100%; padding: 1.75rem 2rem;`).
- أي صفحة جديدة تُنشأ يجب أن تملأ كامل المساحة وتستغل الشاشات العريضة بأريحية تامة.

### هيكل القائمة الجانبية والشريط العلوي:
- **القائمة الجانبية (Sidebar)**: ثابتة بعرض `255px` في الجانب الأيمن (RTL).
- **معلومات المشرف**: مكانها الإلزامي هو **أسفل القائمة الجانبية (Sticky Sidebar Footer)**، وممنوع وضعها في الشريط العلوي (Topbar).
- تحتوي بطاقة المشرف على صورة رمزية (Avatar) تعرض الحرف الأول من اسم المشرف بشكل أنيق ومتركز، مع قائمة منبثقة تفاعلية (Dropdown) تعرض اسم المشرف، بريده، صفته (السوبر أدمن)، روابط الحساب، وزر تسجيل الخروج، وتغلق بالنقر خارجها أو بـ `Esc`.
- **هوية ولوجو البراند (VendorProof)**: اسم المنصة الرسمي هو **VendorProof** (منصة امتثال واعتماد الموردين والشهادات). الشعار الرسمي هو درع التحقق والاعتماد `<i class="ri-shield-check-fill"></i>` داخل مربع بحجم `36px` مكيف للوضعين (فاتح: خلفية `#09090b` وأيقونة بيضاء، ليلي: خلفية `#18191e` وحد `#27272a` وأيقونة ناصعة `#f4f4f5`)، واسم البراند **VendorProof** مع وسم التمييز `.brand-accent`.
- **الشريط العلوي (Topbar)**: مخصص لمسار التنقل (Breadcrumbs)، وحقل البحث السريع مع اختصار `Ctrl+K`، وزر التبديل السلس بين الوضعين الليلي والفاتح (`#themeToggleBtn` مع حفظ في `localStorage` وكود منع الوميض في `<head>`).

### معايير شاشات المصادقة والضيوف (Auth & Guest Pages Standards):
- **الخلفية المتكيفة**: خلفية صفحات المصادقة (`body.auth-page`) يجب دائماً أن تعتمد على `background-color: var(--color-bg);` وممنوع منعاً باتاً وضع أي لون ثابت (مثل `#f8fafc`) لضمان انسيابية الوضع الليلي.
- **قاعدة الزر الأساسي عالي التباين (High-Contrast Inverted Primary CTA)**:

  - **هوفر الوضع الليلي**: يتحول إلى `#e4e4e7` مع **بقاء النص داكناً ومقروءاً `#09090b`**.
- **زر تبديل الثيم العائم (`.auth-theme-switch`)**:
  - إلزامي في شاشات المصادقة والضيوف في أعلى زاوية الصفحة اليسرى (`top: 1.25rem; left: 1.25rem;`) لتسهيل تجربة الوضعين الليلي والفاتح مباشرة.

  - في الوضع الليلي: خلفية داكنة `#18191e` وحدود هيرلاين `#27272a` ونصوص ناصعة، وعند الفوكس تتحول لخلفية `#121316` مع إطار أزرق تقني بارز `#3b82f6`.

### نظام الإشعارات العائمة التفاعلية (Notyf Toast Standards):
- **حظر تام للتنبيهات الثابتة (No Static Flash Banners)**: يُمنع منعاً باتاً كتابة بنرات التنبيه الثابتة المزعجة (`.alert-success` و `.alert-danger`) داخل قوالب Blade لأنها تزيح المحتوى وتخل بالتوازن البصري.
- **التضمين والربط المركزي الموحد**:
  - يتم تضمين الإشعارات حصرياً عبر `@include('admin.partials.notyf')` في قوالب التخطيط الأساسية (`app.blade.php` و `guest.blade.php`) قبل إغلاق `</body>`.
  - الربط التلقائي مع جلسات فلاش لارافيل: يعتمد المتحكم على الطريقة القياسية `->with('success', '...')` و `->with('error', '...')` ويقوم الـ Partial بالتقاطها وتمريرها بأمان عبر `\Illuminate\Support\Js::from(...)`.
  - معالجة أخطاء التحقق (Validation Errors): يتم استخراجها بدون تكرار عبر `array_unique($errors->all())`.
- **هندسة اتجاه RTL وزر الإغلاق والأبعاد**:
  - **الترتيب الإلزامي**: `[أيقونة فكتور Remix Icon على اليمين] -> [نص الرسالة في المنتصف] -> [زر الإغلاق الشفاف على اليسار]`.
  - **حظر الشريط المظلم لزر الإغلاق**: يجب أن تكون خلفية زر الإغلاق شفافة دائماً (`background-color: transparent !important;`) ومثبتة في أقصى اليسار (`left: 8px; right: auto; top: 50%; transform: translateY(-50%)`).
  - **الأبعاد المدمجة**: الارتفاع الأدنى `min-height: 44px`، وهوامش داخلية متناسقة (`padding: 9px 12px 9px 38px`) لمنع تضخم الإشعار.
  - **تعطيل تموج الحركة**: يجب دائماً تعيين `ripple: false` في إعدادات Notyf لمنع تشوهات الحركة الدائرية غير المتوافقة مع RTL.
  - **لوحة الألوان الهادئة الفاخرة**: النجاح (`#15803d` / Emerald هادئ)، الخطأ (`#b91c1c` / Ruby متزن).
  - **الوضع الليلي**: إضافة إطار هيرلاين ناصع `border: 1px solid rgba(255, 255, 255, 0.12)` وظلال عميقة تضمن عزل الإشعار بوضوح عن الخلفيات الكربونية.

### مركزية التنسيقات وحظر الأنماط المدمجة (Strict Zero Inline Styles):
- كافة ملفات التصميم وقواعد الـ CSS توضع حصرياً في [public/css/admin.css](file:///c:/Users/ZBook/Desktop/backend/public/css/admin.css).
- **حظر تام وصارم للإينلاين ستايل (Strictly No Inline Styles)**: يُمنع منعاً باتاً كتابة وسوم `<style>` مدمجة أو سمة `style="..."` داخل أي ملف Blade في كامل المشروع بدون أدنى استثناء. أي تنسيق يجب أن يكون عبر كلاسات CSS مركزية ذات دلالة واضحة في `admin.css`.

## 4. قواعد العمل وسير المهام (Development & Agent Rules)

1. **التخطيط المسبق والموافقة الصريحة دائماً (Strict Plan-First & User Approval)**:
   - يُمنع منعاً باتاً على أي نموذج ذكاء اصطناعي (AI Agent) أو مطور البدء في كتابة أي كود أو تعديل أو تنفيذ أي أمر في المشروع دون تقديم خطة عمل تفصيلية وتوضيحية في وثيقة `implementation_plan.md` وطلب موافقة المستخدم.
   - **الانتظار الإلزامي**: يجب التوقف تماماً (STOP) وعدم لمس أي ملف حتى يمنح المستخدم موافقته الصريحة بالضغط على Proceed أو التصريح المباشر بمتابعة التنفيذ.
2. **التوثيق الفوري في سجل المشروع (`PROJECT_LOG.md`)**:
